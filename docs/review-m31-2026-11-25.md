## 1. 必修（阻塞，一条都不能少）

### D1 `unit.gd:20` —— `has_attacked` 声明成 `= 0`

```gdscript
var has_attacked: bool = 0      # ← 现在这行
```

`bool` 赋整数 `0`，GDScript 会容忍（隐式转 false），但类型标注和值不一致，以后 `:=` 推断或者类型检查会炸。
**改成**：

```gdscript
var has_attacked: bool = false
```

> 预计 1 分钟。

### D2 `unit.gd:58-59` —— keywords 把整个字典塞进去了（**这是最隐蔽的错**）

```gdscript
for k in d.get("keywords",[]):
    newu.keywords.append(str(d))       # ← 追加的是 d，不是 k
```

实测后果（我用探针跑过）：

```
输入 {"keywords": ["blitz","guard"]}
得到 keywords = ["{ \"id\": \"x\", ... 整个字典 ... }", "{ ... 又一份 ... }"]
```

也就是说 `keywords` 里不是 `["blitz","guard"]`，而是两坨 JSON 文本。
所以 `has("blitz")` 恒为 false → **所有闪击相关的判定全部失效**，而且数组长度恰好还是 2，看着"没毛病"。
这也解释了 `[2] 闪击：部署当回合 has_moved = false` 为什么反而"绿"了 —— 它是因为全都没生效才碰巧对的。

**改成**：

```gdscript
newu.keywords.clear()
for k in d.get("keywords", []):
    newu.keywords.append(str(k))
```

> 预计 2 分钟。**改完请自己跑一条探针确认**（下面 §4 给了命令）。

### D3 `unit.gd:121-122` —— `has_keyword()` 签名和实现都不对

```gdscript
func has_keyword() -> bool:
    return not keywords.is_empty()
```

这个函数现在回答的是"这个单位有没有任何关键词"，但名字和 §31 的 API 约定要求的是"**有没有某一个**关键词"。
`can_move()` / `is_blitz()` 全靠它。**改成**：

```gdscript
func has_keyword(kw: String) -> bool:
    return keywords.has(kw)
```

> 预计 1 分钟。

### D4 缺 6 个方法（§31 API 表里的全部）

`grep` 实测：`is_blitz` / `is_tank` / `reset_actions` / `block_actions` / `can_move` / `can_attack` **一个都不存在**。
现在 `battle.gd:215` 能跑是因为它直接写了 `keywords.has("blitz")`，绕过了这些方法；但 `_ai`、`move_unit`、
`attack_unit`、`_settle_status` 四处都需要它们。

加到 `unit.gd` 末尾：

```gdscript
func is_blitz() -> bool:
    return has_keyword("blitz")

func is_tank() -> bool:
    return unit_class == "tank"

## 回合开始：两个动作都恢复
func reset_actions() -> void:
    has_moved = false
    has_attacked = false

## 召唤失调 / 冻结：两个动作都占掉
func block_actions() -> void:
    has_moved = true
    has_attacked = true

## 能不能移动：本回合没移动过；且（没攻击过 或 是坦克）
func can_move() -> bool:
    if has_moved:
        return false
    if has_attacked and not is_tank():
        return false
    return true

## 能不能攻击：本回合没攻击过；且（没移动过 或 是坦克）
func can_attack() -> bool:
    if has_attacked:
        return false
    if has_moved and not is_tank():
        return false
    return true
```

**注意 `can_move` 的两个 `if` 不能合并成一个 `if has_moved or (has_attacked and not is_tank())` 之外的写法**，
也**不能只判 `has_attacked`**——「先移动过就不能再攻击」这条是 `can_attack` 里的 `if has_moved and not is_tank()`，
漏了它 `keywords_test [5] 移动后不能再攻击` 就红（现在就是红的）。

> 预计 15 分钟（含自己验证坦克例外）。

## 4. 这轮踩的坑总结（下次直接用）

1. **`for k in dict.get("key", [])` 里 `append` 的必须是 `k`，不是 `dict`**。用 `str(d)` 会静默塞进整个字典，数组长度还是对的，最难查。
2. **GDScript 的 `bool` 字段被赋 `0` 不报错**，会静默变 false。字段类型和值一定要对上。
3. **函数名要和 §31 API 表一字不差**（`has_keyword(kw)` 不是 `has_keyword()`）。名字差了，调用方全红但报错点离得远。
4. **删字段时要 `grep -rn` 全仓扫一遍**，`src/` 和 `tests/` 都算。GDScript 写不存在的属性**不报错**（动态属性），
   所以"能跑通"不代表"生效了"——这是本项目最容易假绿的地方。
5. **不要为了让测试变绿去改 `tests/`**。测试是验收标准，改它等于自己给自己发合格证。
