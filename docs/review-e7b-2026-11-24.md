## 2. 必修：规格偏差（修完上面才会暴露成断言红）

### D4 · `first_move` 的默认值和注入语义反了

```gdscript
27: var first_move:String = "player"
110: first_move = "player" if rng.randi_range(0,1) else "enemy"
```

两处都要改：

1. **默认值必须是 `""`**（空串 = 还没定先后手），否则 `setup()` 之后没有任何东西表示"开局阶段未定"。
2. **`start_battle()` 必须只在 `first_move == ""` 时随机**。§30 写明这是"可注入"的钩子：

> 可注入：`start_battle()` 只在 `first_move == ""` 时随机。测试要确定性就在 `start_battle()` 前设 `b.first_move = "player"`。

现在的写法是**无条件随机**，于是教练在测试里预设的 `first_move` 会被覆盖掉，
`opening_test[2]`「玩家先手：玩家起手 4 张 / 敌方 5 张」整段必红。

另外 `setup()` 里要把 `first_move` 复位成 `""`（你现在第 55 行只复位了 `opening_phase`）。
`setup()` 的语义是"回到开局之前"，同一战对象复用时会用得到。

顺带提醒：`rng.randi_range(0,1)` 返回的是 **int**，写 `if rng.randi_range(0,1)` 在 GDScript 里不是布尔表达式，
要显式比较 `== 0`（或 `!= 0`），否则报类型错误。参考实现用的就是 `== 0`。

### D5 · `begin_first_turn()` 在敌方先手时把玩家回合吞了

```gdscript
120: func begin_first_turn() -> void:
121: 	opening_phase = false
122: 	if first_move == "player":
123: 		_begin_turn()
124: 	else :
125: 		_enemy_turn()
126: 		if is_over():
127: 			return
```

§30 要求的是：**先手是敌方 → 先跑 `_enemy_turn()`，然后照样进 `_begin_turn()`**。
也就是说 `_begin_turn()` 不在 `if` 里面，而是两条分支都要走到：

```
begin_first_turn():
    opening_phase = false
    if first_move == "enemy": _enemy_turn()
    _begin_turn()            # ← 无论谁先手，最后都要进玩家回合
```

你现在的写法在敌方先手时只跑了 AI 就返回，`turn` 还是 0、玩家没有能量、也没抽牌 ——
`opening_test[4]`「敌方先手：玩家（后手）第 1 回合照常抽 1（5 → 6）」会直接红。

那个 `if is_over(): return` 也一并去掉：`end_turn()` 里已经有 `if is_over(): return` 的守卫，这里重复判断会让
"敌方先手第一回合就把玩家打死"变成静默跳过。

### D6 · `mulligan()` 还是空壳

```gdscript
463: func mulligan(owner: String, cards: Array) -> bool:
464: 	return false
```

`opening_test` 里 [5][6][7][8] 共 10 项检查全指着它。按 §30 的实现要点：

- 守卫顺序（任意一条不满足都必须 `return false`，**且不能改动任何状态**）：
  1. `not opening_phase` → false（开局阶段外）
  2. `cards.is_empty()` → false（空列表）
  3. 该方已经用过（`mulligan_used` / `enemy_mulligan_used`）→ false
  4. 列表里**每一张**都必须是**该方自己的手牌**（`_hand_of(owner).has(c)`），有一张不是 → false
- 全部通过后：把手牌 `erase` → 追加回 `_deck_of(owner)` → 置已用标记 → **洗牌** → `_draw_into(owner, cards.size())`（抽等量）
- 返回 `true`

**洗牌必须用 `Battle.rng` 自己写 Fisher-Yates**（§30 坑 1）：`RandomNumberGenerator` 没有 `shuffle()`，
而 `Array.shuffle()` 用的是全局 RNG，同一个 seed 跑两次结果不同 —— `opening_test[1]` 的「同 seed 两次开局先手相同」
和 `battle_m2_test` 的「同 seed 两局结果一致（run_auto 可复现）」都会因此红。

### D7 · `run_auto()` 少了开局那一步

`start_battle()` 现在不再进回合了，所以 `run_auto()` 里 `start_battle()` 之后必须补一次 `begin_first_turn()`，
否则 `turn` 一直是 0，`while ... turn < max_turns` 的循环条件、以及 AI 的第一次行动全乱。
`battle_m2_test[7]`「自动对局能分出胜负」和 `tools/balance_sim.gd` 都走这条路。

注意：`run_auto()` 里的 `_ai("player")` 仍要保留 —— `begin_first_turn()` 只负责把回合框架立起来，不动玩家手牌。

## 3. 单独提交：`_ai` 攻击前的 Nil 判空（**不要混进 E7b**）

```gdscript
167: elif board.has_unit_of("front") == _opposite(owner):
168: 	for u in board.units_in(_support_of(owner)):
...
171: 		attack_unit(u,board.find_first_unit("front"))
```

前线可能在**同一个循环里被前一次攻击打空**，此时 `find_first_unit("front")` 返回 `null`。
而 `Board.position_of(null)` **不会**返回 `[]` —— 它内部是 `slots[l].find(null)`，会命中空格子，返回一个**假坐标**
（实测 `["enemy_support", 1]`），这个假坐标一路穿过你现有的空值检查，最后在 `attack_unit()` 里访问
`target.owner` 时 **Nil 崩**。

必须先取出来判空再打：

```
var tgt: Unit = board.find_first_unit("front")
if tgt == null: break        # 前线已空，后面的支援单位没有目标
attack_unit(u, tgt)
```

这条 bug 原来被"玩家先手"的执行顺序挡住了；`first_move` 改成随机之后，**敌方先手时必现**（§30 坑 2）。

提交纪律：这个修复**单独一个 `fix(battle): ...` 提交**，在 E7b 的 `feat(battle): ...` 之前。
理由是可回滚粒度 —— 如果 E7b 后面要整体回退，这个独立 bug 修复不该跟着一起消失。
