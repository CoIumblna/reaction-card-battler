## 1. 要改的两处（照着写就行）

### 1.1 `src/core/board.gd:128` —— 给 `has_fighter` 补 `owner` 参数

```gdscript
## 该线上是否有战斗机（owner 非空时只算该方的战斗机）
func has_fighter(line:String, owner:String = "") -> bool:
	for u in units_in(line):
		if u == null or u.is_hq:
			continue
		if owner != "" and u.owner != owner:
			continue
		if u.is_fighter():
			return true
	return false
```

三个细节别省：
- `owner: String = ""` 的默认参数**必须有** —— `board_test` 等地方是单参数调用的，去掉默认值会全线 Parse Error。
- `u == null` 要跳过。`units_in()` 内部其实已经滤过 null，但这是防御：以后有人改 `units_in` 就会在这崩。
- `u.is_hq` 要跳过。HQ 站在支援线 0 号格，它的 `unit_class` 是空串，不会被误判成战斗机；但同一个函数将来
  加别的谓词时，漏掉 `is_hq` 很容易连带出错。**顺手写上是零成本。**
- 用 `u.is_fighter()` 谓词，**不要**再散写 `u.unit_class == "fighter"` —— `unit.gd` 已经有这个谓词（M3.3 加的）。

### 1.2 `src/core/battle.gd` —— 把那一行换成一个判定函数

第 347 行**删掉**，改成：

```gdscript
if not _bomber_target_ok(attacker, target, tar[0]): return false
```

然后在 `_line_span_to()` 之后（文件末尾附近）新增：

```gdscript
## M3.3b：轰炸机攻击「有敌方战斗机驻守的线」时，只能打那一线的战斗机。
## 判定只在「攻击者是轰炸机、且目标不是战斗机」时生效；其余情况一律放行。
func _bomber_target_ok(attacker:Unit, target:Unit, to_line:String) -> bool:
	if not attacker.is_bomber():
		return true
	if target.is_fighter():
		return true
	return not board.has_fighter(to_line, target.owner)
```

为什么拆成函数而不是写一行 `if`：

- 三个前置条件（不是轰炸机 / 目标是战斗机 / 线上无敌方战斗机）各占一行，判错时一眼看出来是哪个条件；
- 和 `_line_span_to()`、`_is_guarded()`、`no_counter()` 的风格一致（`attack_unit` 里现在已经有三个这类谓词调用）；
- 以后 M3.4 加真实空军卡时要补 AI 侧判断，可以直接复用。

## 2. 三个最容易写错的地方（都已实测验证过红绿指纹）

### 坑 A：`to_line` 必须用 `tar[0]`，不是 `at[0]`

`tar` 是目标坐标 `[line, index]`，`at` 是攻击者坐标。轰炸机站 `front` 越线打 `enemy_support`，两线**不同**。
写成 `at[0]` 就是去查攻击者自己那条线（一般是空的）→ **判定恒放行**，等于没写。

实测指纹（参考实现里故意改成 `at[0]`）：**`[1]` `[2]` 红、`[3]` `[4]` 绿**。
`[2]` 是级联红 —— `[1]` 没拒绝就把轰炸机的 `has_attacked` 用掉了，`[2]` 的「去打战斗机」自然也被拒。
**别被 `[3]` `[4]` 的绿骗了**，它俩跟 `to_line` 对不对无关。

### 坑 B：`has_fighter` 不传 `owner` —— 就是你现在这个 bug

写成 `return not board.has_fighter(to_line)`（不传 owner）能通过 `[1]` `[2]` `[3]` 三项，
**只有 2026-11-26 新补的 `[4]` 会红**。所以 `target.owner` 一个字符都不能省。

（`[4]` 是我补的，原因就是你这一版——原来的 3 项测不出这个错。这也是「测试红了先怀疑测试」的又一个实例：
不是测试写错了，是**测漏了**。）

### 坑 C：别顺手改 `_line_span_to()` 和 `no_counter()`

轰炸机打战斗机**仍然会挨反击**，这是 M3.3 定好的规则，`no_counter()` 里「攻击者是轰炸机且目标不是战斗机
才免反击」的写法是对的。本块只加「能不能选中这个目标」，不碰反击。
