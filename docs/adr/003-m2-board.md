# ADR-003：M2 棋盘 —— 三条战线 × 5 格，HQ 20 防

- 状态：已采纳
- 日期：2026-11-08
- 决策人：项目作者（M1 收官后拍板）

## 背景

M1 验证完「出牌 → 伤害 → 元素反应」管线（155 项测试全绿）。
M2 要加空间维度：部署、战线、移动、攻击范围、HQ。

三个必须先定的参数：**战线几何、HQ 数值、位置存在哪**。

## 决策

### 1. 照抄 KARDS 的几何：3 条线 × 每线 5 格

```
        ┌───────────────────────────┐
        │   前线（front，5 格共享）   │
        └───────────────────────────┘
  敌方支援线（5 格，0 号是 HQ）   我方支援线（5 格，0 号是 HQ）
```

- 线名：`enemy_support` / `front` / `player_support`
- 支援线 0 号格固定是 HQ → **每侧实际 4 个单位位**
- 前线 5 格，同一时间只能被一方占据（独占规则在 E11 实现）

### 2. HQ 是 `Unit`，不是新类

- `is_hq = true`、`max_hp = 20`、`attack = 0`、不能移动/攻击
- 放在己方支援线 0 号格
- 胜负：**打掉敌方 HQ → WIN；我方 HQ 被破坏 → LOSE**（不再看"敌人全灭"）

### 3. 位置只存在 `Board`，`Unit` 不存 `line`

- 单一真相源。Unit 只加 `attack` / `has_acted` / `is_hq` 三个字段
- Board 的格子就是数组下标，空位用 `null`

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| 2 线简化（我方支援 + 共享前线） | 状态少一半，E8/E11 简单 | 失去"双侧支援线"的空间感；M3 想加回要重写 Board |
| 3 线 × 4 格 | 局短、单位少、好调试 | 容量常量写死在小值，后期扩展要连测试一起改 |
| **3 线 × 5 格（采纳）** | 与参考规则一致，规则书能逐条对照 | 要处理 HQ 占位：5 格只放得下 4 个单位 |

## 代价

- `Battle` 的回合流程要重写（M1 的"敌人每回合打 4 点"删掉）
- 测试文件从 4 个变 6 个（新增 `board_test` / `combat_test`）
- M1 版 `battle_test` 的 [1]–[7] 大部分不再适用，M2 要重写

## 影响

- 新增 `src/core/board.gd`（`class_name Board`）
- `Unit` 加 3 个字段；位置的归属不在 Unit
- 分片顺序：E1 → E2 → E3 → E6 → E4 → E5 → E7 → E8 → E9 → E10 → E11 → E12 → E13 → E14 → E15
- `Damage.compute()` 原样复用（单位对撞只换调用方，不改算法）
