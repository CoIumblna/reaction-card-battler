## 1. 规则（一句话）

> 目标身上**每 1 层 `defense_down`** → 它**受到的伤害 +1**。
> 单位攻击和指令卡伤害都生效；到期（`duration` 归零）就失效。

`data/tables/statuses.json` 里的定义（**已经在，不用改数据**）：

```json
"defense_down": {
  "name": "减防",
  "effects": [ { "kind": "stat_mod", "stat": "defense", "value": -1.0, "timing": "passive" } ]
}
```

注意 `value` 是 **-1.0**（防御 -1），而我们要的是「受到的伤害 +1」—— **中间差一个负号**。

## 2. 要改的两处（照这个形状写）

### 2.1 `src/core/unit.gd` —— 加 `stat_mod(stat, table) -> int`

插在 `heal()` 之后、`add_buff()` 之前（`unit.gd` 大约第 90 行附近）：

```gdscript
## M3.7 数值系统：把身上所有 passive / stat_mod 效果累加成该属性的修正值（带符号）。
## defense_down 的数据是 { "stat": "defense", "value": -1.0, "timing": "passive" }
## → stat_mod("defense") == -1；防御 -1 意味着「受到的伤害 +1」，取负号的事由 Battle 做。
func stat_mod(stat: String, table: StatusTable) -> int:
	if table == null:
		return 0
	var total: int = 0
	for b in buffs:
		var status: Dictionary = table.get_status(b.kind)
		for e in status.get("effects", []):
			if str(e.get("kind", "")) != "stat_mod":
				continue
			if str(e.get("stat", "")) != stat:
				continue
			if str(e.get("timing", "")) != "passive":
				continue
			total += int(round(float(e.get("value", 0.0)))) * b.stacks
	return total
```

**为什么 `table` 要当参数传**（坑 3）：`Unit` 不持有 `StatusTable`，而 `Buff` 上只有
`kind`/`stacks`/`duration`，**没有 `stat`/`value`** —— 那些在 `data/tables/statuses.json` 里。
`Battle` 有 `status_table` 成员（`battle.gd:26`，`_settle_status()` 就在用），由它传进来最省事。
**不要**给 `Unit` 加一个 `status_table` 成员——那会让单位脱离数据表就不能单测。

### 2.2 `src/core/battle.gd` —— `compute_damage()` 里加算

现在是：

```gdscript
func compute_damage(base_power: int, element: String, target: Unit) -> Dictionary:
	var d := Damage.compute(base_power,element,target,reaction_table)
	return d
```

改成：

```gdscript
func compute_damage(base_power: int, element: String, target: Unit) -> Dictionary:
	var d := Damage.compute(base_power,element,target,reaction_table)
	if not d.get("immune", false):
		var bonus := damage_taken_bonus(target)
		if bonus != 0:
			# 先加算；护盾/免疫在 take_damage() 里扣，天然在后面
			d["damage"] = max(0, int(d["damage"]) + bonus)
	return d


## stat_mod 的语义是「修正属性」，defense -1 → 受到的伤害 +1，所以这里取负号。
## 单位攻击和指令卡伤害都走 compute_damage()，一处改两处生效。
func damage_taken_bonus(target: Unit) -> int:
	if target == null:
		return 0
	return -target.stat_mod("defense", status_table)
```

`damage_taken_bonus` 插在 `compute_damage` 之后即可。

## 3. 五条坑（每条都能让你多花 20 分钟）

1. **`add_buff` 是「叠加不加对象」**。`unit.gd:92` 的 `add_buff()` 遇到同 `kind` 只做
   `b.stacks += 1` 和刷新 `duration`，所以「叠 2 层」在数据上仍是 **1 个 Buff、`stacks == 2`**。
   算伤害要用 `b.stacks` 乘，**不能数 `buffs.size()`**（数了就永远是 1 倍，`[3]` 红）。

2. **减防是「受到的伤害 +1」，不是「攻击力 +1」**。加在 `compute_damage` 的**目标侧**。
   若错加到攻击者的 `attack` 上，`[1]`（无 buff）也会跟着变，红得莫名其妙。

3. **`Unit` 不持有 `status_table`**（见 2.1 的说明）。这是本条唯一的设计决定点，
   别为了省事给 `Unit` 加成员。

4. **`immune` 时不要加减防**。`Damage.compute()` 返回的 `immune == true` 表示元素免疫，
   此时伤害本来就是 0/无效，再加 `defense_down` 会算出「免疫还掉血」的怪结果。

5. **别改 `Damage.compute()` 的返回字典形状，也别把减防塞进 `damage.gd`**。
   `damage.gd` 的 `compute()` 是 `static`（访问不到实例的 `status_table`），且
   `combat_test`/`damage_test`/`status_test` 里有大量 `hit["damage"]` 断言。
   在 `battle.gd` 的实例方法里外层加算、让 `Damage.compute()` 保持纯函数，最安全。
