## 1. 规则（一句话）

> 目标身上**每 1 层 `defense_down`** → 它**受到的伤害 +1**。单位攻击和指令卡伤害都生效；到期就失效。

`data/tables/statuses.json` 里的定义**已经在，不用改数据**：

```json
"defense_down": {
  "name": "减防",
  "effects": [ { "kind": "stat_mod", "stat": "defense", "value": -1.0, "timing": "passive" } ]
}
```

`value` 是 **-1.0**（防御 -1），我们要的是「受到的伤害 +1」—— **中间差一个负号**。

## 2. 写在哪里？两种都行，选一种

> **先回答你的问题**：`stat_mod` **不是必须写在 `Unit` 里**。文档 §36 原来那句
> `target.stat_mod("defense")` 和坑 3「Unit 不持有 status_table」是矛盾的（一个不传参、一个说必须传），
> 这是我的文档 bug，已订正。**两种写法我都验证过，都是 7/7。**

### 方案 B（推荐）：只改 `src/core/battle.gd`，`unit.gd` 一行都不用动

「减防 → 受伤 +1」本来就是**战斗规则**，不是单位自身的属性。所以加值计算留在 `Battle` 里最直接——
`Battle` 的 `status_table` 就是成员（`battle.gd:26`），**不存在传参问题**。

`src/core/battle.gd:272` 现在是：

```gdscript
func compute_damage(base_power: int, element: String, target: Unit) -> Dictionary:
	var d := Damage.compute(base_power,element,target,reaction_table)
	return d
```

改成：

```gdscript
func compute_damage(base_power: int, element: String, target: Unit) -> Dictionary:
	var d := Damage.compute(base_power,element,target,reaction_table)
	if not d.get("immune", false):
		var bonus := damage_taken_bonus(target)
		if bonus != 0:
			d["damage"] = max(0, int(d["damage"]) + bonus)
	return d


## defense_down 的数据是 { "stat": "defense", "value": -1.0, "timing": "passive" }
## → 防御 -1 意味着「受到的伤害 +1」，所以最后取负号。
func damage_taken_bonus(target: Unit) -> int:
	if target == null:
		return 0
	var total: int = 0
	for b in target.buffs:
		var status: Dictionary = status_table.get_status(b.kind)
		for e in status.get("effects", []):
			if str(e.get("kind", "")) != "stat_mod":
				continue
			if str(e.get("stat", "")) != "defense":
				continue
			if str(e.get("timing", "")) != "passive":
				continue
			total += int(round(float(e.get("value", 0.0)))) * b.stacks
	return -total
```

`damage_taken_bonus` 紧接在 `compute_damage` 后面即可。**方案 B 实测：7/7 PASS、主套 449/449。**

### 方案 A：属性查询下放到 `Unit`，那就必须传 `table`

`src/core/unit.gd` 在 `heal()`（第 87 行结束）之后、`add_buff()`（第 92 行）之前插入：

```gdscript
func stat_mod(stat: String, table: StatusTable) -> int:
	if table == null:
		return 0
	var total: int = 0
	for b in buffs:
		var status: Dictionary = table.get_status(b.kind)
		for e in status.get("effects", []):
			if str(e.get("kind", "")) != "stat_mod":
				continue
			if str(e.get("stat", "")) != stat:
				continue
			if str(e.get("timing", "")) != "passive":
				continue
			total += int(round(float(e.get("value", 0.0)))) * b.stacks
	return total
```

**注意签名是 `stat_mod(stat, table)` 两个参数** —— 文档里 `target.stat_mod("defense")`（一个参数）是错的。
`battle.gd` 里就变成：

```gdscript
func damage_taken_bonus(target: Unit) -> int:
	if target == null:
		return 0
	return -target.stat_mod("defense", status_table)
```

> **为什么必须传 `table`**：`Unit` 不持有 `StatusTable`；而 `Buff` 上只有 `kind`/`stacks`/`duration`
> （看 `src/core/buff.gd`，就这三个字段），**没有 `stat` / `value`**。`-1.0` 这个数字在
> `data/tables/statuses.json` 里，由 `StatusTable` 持有。`Battle` 有 `status_table` 成员，
> 由它传进去。**不要**给 `Unit` 加 `status_table` 成员——那会让单位脱离数据表就不能单测。

**方案 A 我也实测过：同样 7/7 PASS、主套 449/449。** 两种等价，选写得顺手的。

## 3. 五条坑（每条都能让你多花 20 分钟）

1. **算伤害要用 `b.stacks`，不能数 `buffs.size()`**。`unit.gd:92` 的 `add_buff()` 遇到同 `kind` 只做
   `b.stacks += 1` 和刷新 `duration`，所以「叠 2 层」在数据上仍是 **1 个 Buff、`stacks == 2`**。
   数 `buffs.size()` 就永远算 1 倍，`[3]` 红。

2. **减防是「受到的伤害 +1」，不是「攻击力 +1」**。加在 `compute_damage` 的**目标侧**。
   错加到攻击者的 `attack` 上，`[1]`（无 buff）也会跟着变。

3. **`Unit` 不持有 `status_table`**，`Buff` 也没有 `stat`/`value`。要么按方案 B 在 `Battle` 里算，
   要么按方案 A 把 `StatusTable` 当参数传进去。别给 `Unit` 加 `status_table` 成员。

4. **`immune` 时不要加减防**。`Damage.compute()` 返回 `immune == true` 表示元素免疫，此时伤害本来
   就是 0/无效，再加 `defense_down` 会算出「免疫还掉血」。

5. **别改 `damage.gd`**。`Damage.compute()` 是 `static`（访问不到实例的 `status_table`），且
   `combat_test`/`damage_test`/`status_test` 里有大量 `hit["damage"]` 断言。在 `battle.gd` 的实例方法
   里外层加算、让 `Damage.compute()` 保持纯函数，最安全。
