# 游戏设计文档（GDD）· 元素反应卡牌战斗

> 参考方向：**KARDS 式**（战场空间 + 费用曲线），而不是七圣召唤（骰子）或杀戮尖塔（单人 Roguelike）。
> 规则底稿见 `docs/kards-rules-reference.md`；决策记录见 `docs/adr/002-m1-scope.md`。

## 版本路线（已定）

| 阶段 | 玩法范围 | 目标 |
|---|---|---|
| **M1（现在）** | **无战线**：单目标战斗，只验证「出牌 → 伤害 → 元素反应」这条管线 | 把规则内核和测试骨架跑通 |
| **M2** | 加**部署、战线、移动、行动花费**，变成 KARDS-lite | 从"打木桩"变成"下棋" |
| M3 | 关键词（闪击等）+ 卡组构筑 + 平衡模拟 | 有策略深度 |
| M4 | 界面、存档、发布 | 能玩、能给人看 |

> **M1 不是成品玩法，是"测试台"**：它的价值是让你在没有棋盘复杂度的情况下，
> 把伤害公式、反应查表、状态结算、日志、测试这些"地基"打对。

## M1 具体规则（已定）

### 一局是什么样

```
玩家（60 HP）  vs  一个敌人（24 HP）
每回合：能量回满 3 点 → 抽到 5 张手牌 → 出牌（消耗能量）
       → 敌人反击 4 点（占位规则，M2 换成真正的单位）→ 下一回合
谁先被打空血谁输
```

### 参数

| 项 | 值 | 说明 |
|---|---|---|
| 玩家 HP | 60 | 能撑 15 回合左右 |
| 敌人 HP | 24 / 40 | 见 `data/tables/enemies.json` |
| 每回合能量 | 3 | 固定（M2 才改成 Kredit 增长） |
| 手牌 | 抽到 5 张 | 每回合补满 |
| 敌人在 M1 的行为 | 每回合打玩家 4 点 | **占位**，M2 换成单位 AI |
| 胜利 | 敌人全灭 | |
| 失败 | 玩家 HP 归零 | |

### 卡牌（M1 三类）

| 类型 | 效果 |
|---|---|
| `damage` | 按 `元素 × 目标附着` 结算伤害，可能触发反应 |
| `shield` | 给玩家加护盾（先扛伤害） |
| `heal` | 给玩家回血（不超上限） |

### 元素反应（M1 唯一的核心玩法）

- 攻击结算时：`Damage.compute(基础值, 攻击元素, 目标附着, 反应表)`
- 有反应 → 伤害 × 倍率；无反应 → ×1.0
- 反应的具体数值与附着规则：**你写在 `docs/element-reactions.md`**

M1 里"元素反应"体现在**出牌顺序**上：先用水卡给敌人挂水，再用火卡打，伤害 ×1.5。
这就已经是"有策略"的最小形态了。

## M2 会加什么（现在只需知道方向，不要提前写）

| 新机制 | 会改动哪里 |
|---|---|
| 双方 HQ（20 防） | 胜负判断从"敌人血条"变成"打掉 HQ" |
| Kredit 1→N 增长 | 能量从固定 3 改成随回合增长 |
| 单位部署 + 召唤失调 | `Card` 加单位类型，`Battle` 加场面状态 |
| 战线（支援/前线）+ 移动 | `Battle` 加位置与移动逻辑，**这是最大的一块** |
| 行动花费 | 移动/攻击要额外付费 |
| 单位对撞 | `Damage.compute()` **原样复用**（所以 M1 才要把它抽出来） |

> M1 的代码不会白写：`Damage`、`ReactionTable`、`DataLoader`、`Unit` 在 M2 全部继续用，
> 只有 `Battle` 的回合流程要重写。**这就是"先做可测试的部分"的价值。**

## 还需要你定的（M1 内）

| # | 问题 | 影响 |
|---|---|---|
| 1 | 反应表数值（3 条反应的倍率/附加状态） | 决定伤害手感，写 `reactions.json` |
| 2 | 附着规则：反应后附着消耗还是保留？ | 决定 `_apply_aura()` 怎么写 |
| 3 | 单张卡强度基准（1 费 ≈ 多少伤害？） | 决定 20 张卡的数值 |
| 4 | 敌人 AI 在 M1 要不要换花样（比如每 3 回合重击一次） | 可选，不影响架构 |

## 设计红线（M1 不做）

- ❌ 不做战线 / 部署 / 移动 / 行动花费（M2）
- ❌ 不做 Kredit 成长、卡组构筑、国家阵营（M2-M3）
- ❌ 不做兵科（步兵/坦克/炮兵…）（M2）
- ❌ 不做存档、多关卡、动画（M4）
- ❌ 不做联机
