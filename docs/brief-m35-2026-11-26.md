## 1. 这件事到底要做什么

游戏里「牌组」和「卡牌库」是两个东西：

| 概念 | 文件 | 形态 |
|---|---|---|
| 卡牌库（所有卡的模板） | `data/tables/cards.json` | `"cards": [ {id, name, cost, ...} ]`，每条带 `count` |
| **牌组**（某一副具体 39 张） | `data/decks/player_deck.json` | `"cards": [ { "id": "footman", "count": 4 }, ... ]` |

牌组文件里**只写 id + 张数**，不重复卡片数据。所以 `load_deck()` 要做的事是：

> 读牌组文件 → 按 id 去卡牌库里查模板 → 把每张展开成 **39 个独立的 `Card` 对象**。

现在 `load_cards()` 已经会按 `cards.json` 的 `count` 展开**整库**（那是给开发期用的），
`load_deck()` 是**按牌组清单**展开。两者别混。

---

## 2. 规则（这些是硬约束，测试逐条验）

| 项 | 值 |
|---|---|
| 张数 | **恰好 39 张**（不是 ≤39，也不是「任意」） |
| 同名上限 | 同一个 id 最多 **4** 张 |
| 非法输入 | 一律 `push_error` + **返回空数组**（不是返回部分结果） |
| 返回类型 | `Array[Card]`，**每张都是独立对象**（不能共享引用） |
| 文件路径 | 默认参数指向 `data/decks/player_deck.json`，但**必须能被调用方改**（测试会传临时路径） |

关于「独立对象」这条，测试是这么验的：加载两次，要求
- 两个数组**不是同一个引用**（`is_same` 判，不是 `==`）
- 数组里的 `Card` 对象**也不共享引用**

> 这里有个 GDScript 陷阱：`Array` 的 `==` 是**内容比较**（`[1,2,3] == [1,2,3]` 为 true），
> 判「是不是同一个对象」必须用 `is_same(a, b)`。测试里就是这么写的，你实现时不用管，
> 但你要明白：**如果所有 Card 都指向同一个 `Card.from_dict()` 结果，测试会红。**

## 3. 必须两遍走，不能一遍走完

这是本块最容易写错的地方。一遍循环里「边校验边展开」会出问题：

- 如果某张卡在第 20 条才发现非法，你已经往结果里塞了 19 条 —— 返回什么？
  规则要求「非法 → 返回空数组」，那前面那些就白塞了；
- 更麻烦的是 `count` 非法（0 或负数）时，你可能在 `range()` 里就崩了。

所以要 **pass 1 全量校验、pass 2 才展开**：

```
pass 1：逐条看牌组清单
        - id 在卡牌库里存在吗？
        - count 是正整数吗？
        - 按 id 累加，累加后有没有超过 4？
        - 累加总数（或展开时统计），最后是不是 39？
        → 任何一条不合格：push_error，直接返回 []
pass 2：确认全部合法后，再逐条展开成 Card
```

**累加**这个词很关键：同一 id 可能在清单里出现**多行**（比如 `footman` 写两次各 2 张），
上限 4 判的是**所有行加起来**，不是单行。

## 4. 「卡牌库」怎么查

`load_cards()` 现在的读法是「读文件 → 逐条 `Card.from_dict`」，它在读的过程中展开。
你需要一份 **id → 模板字典** 的映射。两种做法：

- **A**：写一个私有辅助 `_card_catalog()`，把 `cards.json` 读成一个 `Dictionary`（id → 那条原始 dict）。
  `load_cards()` 可以继续用现在的方式（不必为此重构）。
- **B**：让 `load_deck()` 内部自己 `load_json()` 再建映射，不新增函数。

A 更好一点（以后加卡牌编辑器、卡组编辑器都要「查一张卡」），但**A 不是必须的**。
选哪个都行，别为了「优雅」把 `load_cards()` 改出红来 —— 主套里有 46 项 `data_test` 依赖它。

## 5. 三条判据（自己验，不用告诉我）

1. **改数据要跟着变**：把 `player_deck.json` 里某个 `count` 从 4 改成 3，
   那么总数变 38 → 应该报「必须 39」。改回来又绿。这说明你没把 39 写死成「不校验」。
2. **故意写坏一条**：把某个 `id` 改成不存在的（如 `"no_such_card"`），
   应该 `push_error` 且返回空数组（不是返回剩下的 38 张）。
3. **同名超限**：某 id 写成 `count: 5`，应该报「超过上限 4」。

---

## 6. 四条坑

1. **`Array[Card]` 是类型化数组，返回 `[]` 时也要是空的 `Array[Card]`**。
   直接 `return []` 在声明返回 `Array[Card]` 的函数里通常没问题，但如果写
   `var out = []` 再 `return out`，就成了无类型 `Array` → 运行时报类型不匹配。
   要么 `var out: Array[Card] = []`，要么返回前保证类型。
2. **`Card.from_dict()` 每张单独调一次**。卡牌库里的模板复用同一条 dict 没关系
   （`from_dict` 会 new 出新对象），但**不能把同一张 `Card` 塞 4 次**。
3. **非法时不要「边报错边继续」**。`push_error` 之后要 `return []`，
   否则测试拿到 38 张会红得莫名其妙（它期望 `size() == 0`）。
4. **`load_json()` 返回 `{}` 表示失败**（文件不存在 / 解析失败，它自己已经 `push_error` 了）。
   `load_deck()` 里要判这个空字典，别拿它去 `get("cards")` 然后当成「牌组是空的」。
