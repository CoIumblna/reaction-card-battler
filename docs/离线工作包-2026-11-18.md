## T1 `_enemy_ai()` 三段（约 1.2h）

**改哪里**：`src/core/battle.gd`，现在是 `func _enemy_ai() -> void: pass`。

**照 `docs/implementation-tasks.md` §23 的两张表写**（表格里写了每段的顺序、条件、扣谁的钱）。三段：

1. **部署**（每回合最多 1 张）：从 `enemy_hand` 挑**最贵的、付得起的**单位卡 → `_deploy_unit(card, "enemy")`
2. **推进**：`front` 里没有玩家单位时，把 `enemy_support` 里**每个非 HQ、未行动**的单位各推一次 → `move_unit(u, "front", slot)`
3. **攻击**：**每个未行动**的敌方单位各攻击一次 → `attack_unit(u, target)`；目标在**相邻线**里：**先找玩家 HQ**，找不到 HQ 才打玩家单位

**两个坑**（§23 的"坑"小节也写了）：
- `attack_unit(x, null)` 会崩 → 选目标前先判空
- `units_in()` 会把 HQ 一起返回 → 挑候选时 `if u.is_hq: continue`

**验收**：`tools\check.bat` → E15 检查点 6/7（最后一条"自动对局"还红是正常的，那是 T2 的事）。
也可以单跑：`--headless --path . --script res://tests/battle_m2_test.gd`，看 `[6]` 那 17 条。

**卡住提示**：`battle_m2_test` 的 `[6]` 有 5 个用例，分别考"部署 / 推进 / 攻击 HQ / 支援线打不到 HQ 就打单位 / 敌方 has_acted 清零"——哪条红就对着那个用例读断言，别猜。

**提交**：`feat(battle): 敌方 AI 三段（E15 第 3 块）`

## T4 C8：状态效果生效（约 1.5h）

**第一步：启用测试**（这条测试我已经写好了，现在放在 `tests\pending\` 不跑）

把 `tests\pending\status_test.gd` **剪切到 `tests\` 下**。runner 会自动发现它（`run_tests.bat` 和 CI 都是自动扫 `tests\*_test.gd`），
不用改任何脚本。移过去后 `tools\check.bat` 会显示 `status_test` **12 条检查、其中 9 条红**（另外 3 条是碰巧绿的，
比如"burn 还在"只是因为没人 tick），全部做完才是 12/12。

**第二步：照 `docs/implementation-tasks.md` §24 实现**：

1. `Battle` 加 `status_table` 字段，`setup()` 里加载 `res://data/tables/statuses.json`
2. **回合开始的四步，顺序不能换**：① dot 掉血 → ② 死亡移除 → ③ disable 标记 → ④ `tick_buffs()`。
   玩家单位在 `_begin_turn()`、敌方单位在 `_enemy_turn()` 里各做一次（跳过 HQ）
3. 反应挂状态：反应结算层遍历 `effects`，`kind == "status"` → 目标 `add_buff(Buff.make(id, int(duration)))`

**验收**：`status_test` 12/12：
- `[0]` 数据接线 1 条
- `[1]` dot 4 条（燃烧 duration 2 → 两个回合各掉 1 血，然后移除）
- `[2]` disable 3 条（冻结 1 回合 → 当回合不能动，下回合恢复）
- `[3]` 反应挂状态 4 条（感电 → shock 2 回合；冻结 → immobilized）

**坑**：
- 四步顺序：dot 在 tick **之前**（否则 duration 1 的冻结会先过期、燃烧少掉一次）；disable 判定也在 tick 之前
- 伤害取整 `int(floor(value * stacks))`，走 `take_damage`（护盾先吸收）
- 同一状态重复挂 → `stacks + 1`、duration 取大，别叠两个 Buff（否则 dot 翻倍）
- `statuses.json` 里查不到的 buff.kind → 当没有效果，不要崩

**提交**：`feat(battle): 状态效果生效（C8）`

## 验收工具怎么用

| 命令 | 用途 |
|---|---|
| `tools\check.bat` | **日常用这个**：跑全套 + 进度表 + E15/C8 检查点 + 下一步建议 |
| `run_tests.bat` | 严格版（提交前跑）：每个文件要求 退出码 0 + 有 `PASS` + 无 `[FAIL]` + 无 `SCRIPT ERROR`，并返回真实退出码 |
| 单文件 | `& $g --headless --path . --script res://tests/battle_m2_test.gd`（改一点跑一点，比全套快） |

工具找不到 Godot 时：改 `run_tests.bat` 第 4 行，或 `tools\check.ps1` 顶部的 `-Godot` 参数。

## 离线纪律（重要）

1. **每完成一段就 `check.bat` 一次**；红条数只能减，不能增（增了就是回归）
2. **不许改 `tests/`、`data/`、`docs/` 来让测试变绿**（那是放水）。规格问题记下来发我，回来一起改
3. 卡住 20 分钟：先读 `docs/implementation-tasks.md` 对应小节 → 再看 `..\_reference_battler`
   （那是 M1 版，**棋盘/敌方 AI 没有参考**，别硬套）
4. 提交用消息文件：`git commit -F <文件>`；格式「类型(范围): 中文摘要」，一次一块
5. 每块结束写 3 行 `devlog.md`

## 常见问题

| 现象 | 处理 |
|---|---|
| 改了 `.gd` 后测试行为没变 | 先 `--import`（check.bat / run_tests.bat 会自动做） |
| 退出码 0 但有 `SCRIPT ERROR` | 假绿。看 check.bat 的 SCRIPT ERROR 列，非 0 就是红了 |
| `战斗日志`/`共 N 项检查` 里的 N 比预期少 | 有测试段被跳过（多半是前置 `return`），看红的那条提示 |
| Godot 报 `Cannot save editor_settings` | 无害，是你家/外面机器的用户目录权限，跟项目无关 |
